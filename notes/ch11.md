# ch11 - function overloading and function templates

### 11.1 - introduction to function overloading 
- - -
- **function overloading** allows us to create multiple functions with the same name, each function sharing the same name in the same scope is called an **overloaded** function
- functions can be overloaded as long as each overloaded function can be differentiated by the compiler, if it cannot be differentiated then it results in a compile error
- to overload a function, you can declare another function with the same name which takes different type of parameters
- when a function call is made to a function that has been overloaded, the compiler will try to match the function call to the appropriate overload based on the arguments used in the function call, this is called **overload resolution**

### 11.2 - function overload differentiation
- - -
- the properties of a function used to differentiate it from others are: **number of parameters** and **type of parameters**
- note that the return type of a function is not used to differentiate it from other functions with the same identifier, doing only that will result in a compile error, however a different return type with different type of parameters is completely valid 
- a function's **type signature** is defined as the parts of the function header that are used for differentiation of that function, like stated above it includes the function name, number of parameters and parameter type, but does not include the return type of the function 

### 11.3 - function overload resolution and ambiguous matches
- - -
- the process of matching function calls to a specific overloaded function is called **overload resolution**
- when a function call is made to an overloaded function, the compiler steps through a sequence of rules to determine which of the overloaded functions is the best match
- there are three possible outcomes from this:
    1. no matching functions are found, the compiler moves to the next step in the sequence
    2. a single matching function is found (this is considered the best and the matching process is complete)
    3. more than one matching function is found, the compiler generates an error 
- **trivial conversions** are a set of specific conversion rules that will modify types (without modifying the value) for the purpose of finding a match
- the argument matching sequence happens in two phases, the first phase is where the compiler checks for an overloaded function where the type of the arguments in the function matches the type of the parameters in the overloaded functions and the second phase is where the compiler applies a number of trivial conversions to the arguments in a function call
- note that matches made with trivial conversions are considered exact matches, so the following functions `void foo(int)` and `void foo(const int)` result in a ambiguous match compile error
- if no exact match is found, then the compiler tries to find a match by applying numeric promotion to the arguments 
- if no match is found even after numeric promotion, then the compiler tries to find a match by applying numeric conversions
- if no match is found even after numeric conversions, then the compiler tries to find a match through user defined conversions (not yet discussed, but to be noted)
- if no match is found through user defined conversions, then the compiler will look for a matching function that uses ellipsis (again, not yet discussed but to be noted)
- if no matches have been found by this point, then the compiler gives up and issues a compile error 
- an **ambiguous match** occurs when the compiler finds two or more functions than can be made to match in the same step 
- to fix this, you can either define a new overloaded function that takes parameters of the type you are trying to call the function with, or you can static cast the arguments while calling the function so the compiler knows which one you are trying to call
- if there are multiple arguments, the compiler applies the matching rules to each argument in the call, the function chosen is the one where each argument matches at least as well as the other functions while having at least one argument that matches better than all the other functions
