# ch7 - scope, duration and linkage

### 7.1 - compound statements (blocks)
- - -
- a **compound** statement (also called a **block**) is a group of zero or more statements that are treated by the compiler as if it were a single statement
- blocks begin with a `{` and end with `}`
- functions can't be nested inside other functions, but blocks can be nested inside other blocks where the enclosing block is called the **outer block** and the enclosed block is called **inner/nested block**
- the **nesting level** of a function is the maximum number of nested blocks you can be inside at any point in the function, the maximum number of levels supported for now is 256

### 7.2 - user defined namespaces and the scope resolution operator
- - -
- cpp allows us to define our own namespace, namespaces that you create in your own programs are called **user-defined/program-defined** namespaces
- the namespace must be defined in the global scope, or inside of another namespace
- the best way to tell the compiler to look inside a particular namespace for an identifier is to use the **scope resolution operator** (`::`)
- when you use the scope resolution operator in front of an identifier without providing a namespace name, it will look for the identifier in the global namespace, this is useful when you are inside of a namespace and explicitly want to call a function from the global namespace
- when using namespaces with header, the forward declarations also need to be in the same namespace 
- it is legal to declare namespace blocks in multiple locations, all declarations within the namespace are considered part of the namespace
- namespaces can be nested, meaning you can declare a namespace within another namespace
- you can use namespace aliases to temporarily shorten the name of a namespace, for testing purposes

### 7.3 - local variables 
- - -
- local variables have block scope, meaning they are in scope from their point of definition till the end of the block in which they are defined
- a variable's **storage duration** determines what rules govern and when and how a variable will be created and destroyed, in most cases this duration directly determines a variable's lifetime
- local variables have automatic storage duration, meaning they are created at the point of definition and are destroyed at the end of the block, which is why they are also called automatic variables sometimes
- nested blocks are considered to be a part of the scope of the outer block in which they are defined, so for this reason the variables defined in the outer block can be seen inside a nested block
- identifiers have a property known as **linkage**, an identifier's linkage determines whether a declaration of that same identifier in a different scope refers to the same object
- scope determines where an identifier can be seen and used, linkage determines whether multiple declarations of the same identifier refer to the same object or not
