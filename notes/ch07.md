# ch7 - scope, duration and linkage

### 7.1 - compound statements (blocks)
- - -
- a **compound** statement (also called a **block**) is a group of zero or more statements that are treated by the compiler as if it were a single statement
- blocks begin with a `{` and end with `}`
- functions can't be nested inside other functions, but blocks can be nested inside other blocks where the enclosing block is called the **outer block** and the enclosed block is called **inner/nested block**
- the **nesting level** of a function is the maximum number of nested blocks you can be inside at any point in the function, the maximum number of levels supported for now is 256

### 7.2 - user defined namespaces and the scope resolution operator
- - -
- cpp allows us to define our own namespace, namespaces that you create in your own programs are called **user-defined/program-defined** namespaces
- the namespace must be defined in the global scope, or inside of another namespace
- the best way to tell the compiler to look inside a particular namespace for an identifier is to use the **scope resolution operator** (`::`)
- when you use the scope resolution operator in front of an identifier without providing a namespace name, it will look for the identifier in the global namespace, this is useful when you are inside of a namespace and explicitly want to call a function from the global namespace
- when using namespaces with header, the forward declarations also need to be in the same namespace 
- it is legal to declare namespace blocks in multiple locations, all declarations within the namespace are considered part of the namespace
- namespaces can be nested, meaning you can declare a namespace within another namespace
- you can use namespace aliases to temporarily shorten the name of a namespace, for testing purposes

### 7.3 - local variables 
- - -
- local variables have block scope, meaning they are in scope from their point of definition till the end of the block in which they are defined
- a variable's **storage duration** determines what rules govern and when and how a variable will be created and destroyed, in most cases this duration directly determines a variable's lifetime
- local variables have automatic storage duration, meaning they are created at the point of definition and are destroyed at the end of the block, which is why they are also called automatic variables sometimes
- nested blocks are considered to be a part of the scope of the outer block in which they are defined, so for this reason the variables defined in the outer block can be seen inside a nested block
- identifiers have a property known as **linkage**, an identifier's linkage determines whether a declaration of that same identifier in a different scope refers to the same object
- scope determines where an identifier can be seen and used, linkage determines whether multiple declarations of the same identifier refer to the same object or not

### 7.4 - introduction to global variables
- - -
- you can also declare variables outside of a function, such variables are known as **global variables**
- global variables are usually declared at the top of the program file, below the header inclusions, in the global namespace
- these variables have a **global namespace scope** (also called global scope or file scope), which means they are visible from the point of declaration until the end of the file in which they are declared
- global variables can also be defined inside a user-defined namespace, it makes the identifier of the global variable limited to the scope of the namespace but, the name and variable itself are still globally accessible (read the example in 7.4 if you didn't understand), it is usually recommended to define global variables inside a user-defined namespace instead of just the global namespace
- these variables are created when the program starts and they're destroyed when it ends, this is called **static duration**, variables with a static duration are sometimes referred to as **static variables**
- to differentiate global variables from local ones, you use the prefix 'g_' or just 'g', however you can omit it if you are defining it inside of a user-defined namespace since it serves the same purpose
- global variables are zero-initialized by default, unlike local ones which are uninitialized

### 7.5 - variable shadowing (name hiding)
- - -
- when we have a variable that is nested inside a block, with the same name as a variable from the outer block, the nested variables temporarily hides the outer variable in areas where they are both in scope, this is called **name hiding** or **shadowing**
- when inside a nested block, there is no way you can directly access the shadowed variable from the outer block
- similar to how the nested variable shadows the variable from the outer block, a local variable also shadows a global variable with the same name in areas where they are both in scope, however since global variables are part of the global namespace, we can use the scope operator (`::`) with no prefix to tell the compiler we want to access the global variable

### 7.6 - internal linkage
- - -
- if you forgot what linkage is: it just answers one question: "if i use this name in different places, does it refer to the same thing or different things?"
- there are three types of linkage: no linkage, internal linkage and external linkage
- a variable/function with **internal linkage** is only visible/usable inside the one file it's defined in, your other files have no idea it even exists
- global variables with internal linkage are sometimes referred to as internal variables
- to make a non-constant global variable internal, you have to use the `static` keyword, otherwise it defaults to external linkage
- const and constexpr global variables have internal linkage by default and don't need the `static` keyword
- functions also default to external linkage and can be set to internal linkage with the `static` keyword
- note that identifiers with internal linkage aren't exposed to the linker
